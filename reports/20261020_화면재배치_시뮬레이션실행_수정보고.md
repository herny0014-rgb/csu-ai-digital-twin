# 수정 보고 — 화면 정리 및 배치 변경 (시뮬레이션 실행 버튼 통합)

> ※ 이 문서는 해당 단계 작성 당시의 기록입니다. 이후 화면이 다시 바뀌었고, 커밋·푸시·배포 항목은 당시 상태입니다. **최종 구현 상태와 저장·배포 결과는 `20261021_최종_작업보고.md`를 기준으로 합니다.**

- **일자:** 2026.10.20
- **대상:** CSU AI 하역 디지털 트윈 (`streamlit_app.py`, `README.md`)
- **구분:** 화면 개편 (로컬 수정과 검증까지만, 커밋·푸시·배포 없음)
- **목적:** 브랜드별 슈트 막힘 이력 기반 적정 하역률(t/h)을 간결하게 보여 주는 PoC 화면

## 1. 새 화면 순서

| 순서 | 영역 | 비고 |
| --- | --- | --- |
| 1 | 브랜드 선택 | 직접 입력 기능 유지 |
| 2 | 슈트 막힘 이력·조건 | 위로 이동, 제목·설명 정리, 흰 배경 제목 문제 수정 |
| 3 | 시뮬레이션 실행 버튼 | 운전 모드·조업 착수·조업 정지를 이 버튼 하나로 통합 |
| 4 | 추천 하역률(t/h)과 추천 근거 | 핵심 수치 하나를 크게 표시 |
| 5 | 원료 이송 흐름도 | 유지, 모드 종속 문구 정리 |
| 6 | 컨베이어 실시간 운전 데이터 | 유지 (BOOM / FEEDER / GANTRY 속도·모터 부하·토크) |

## 2. 삭제한 것

| 구분 | 내용 |
| --- | --- |
| 모드·버튼 | 운전 모드(수동/AI 자동), 조업 착수, 조업 정지, 수동 모드 안내 문구 |
| 입력 | 버켓 속도, 디깅 깊이, 선박 적재 화물량, BOOM·FEEDER·GANTRY 속도 슬라이더, 사행·편적 감지 신호 |
| 영역 | 컨베이어 벨트 속도 제어, 사행·편적 감지 조건, 사행·편적 AI 예방감시 |
| 관련 코드 | 사행 위험도 계산과 예방 감속 로직, 잔량 처리 카운트다운, AI 실시간 자동제어 표시 줄, 수동 모드 흔들림 계산, 상태 메시지 |
| 기존 삭제 유지 | AI 학습용 데이터 수집, 회사 실제 운전 데이터 입력, 실시간 운전 데이터 제목과 지표 6개는 다시 넣지 않음 |

## 3. 숨긴 입력값의 처리

- 입력을 없앤 값은 **선택한 브랜드의 기존 운전값**(`BRAND_AI_PROFILES`, 없으면 `DEFAULT_AI_PROFILE`)과 **기존 계산식**을 그대로 사용한다. 새 수식은 만들지 않았다.
- 사행 계산과 예방 감속은 제거했다. 사행 감지 신호의 기본값(15%)에서는 11개 브랜드와 직접 입력 모두 감속 기준(55%)에 닿지 않아 원래도 작동하지 않던 경로이다. 실제로 12개 경우 모두 이전 AI 자동 모드와 하역량·부하·속도·적재율이 똑같이 나오는 것을 확인했다.
- 계측값으로 오인되지 않게 한 표시:
  - 흐름도 오른쪽 패널: "AI CONTROL 수동" → "시뮬레이션 설정 · 가상 조건", "AI 판단" → "브랜드별 발표용 운전값 기준 · 실제 계측값이 아닙니다"
  - 흐름도 왼쪽 패널: 로드셀 상태 문구 → "시뮬레이션 값 · 실제 계측값 아님"
  - 컨베이어 실시간 운전 데이터: "시뮬레이션 값이며 실제 설비 계측값이 아닙니다" 안내 추가
  - "실제 누적 하역량" → "누적 하역량 (시뮬레이션)" (흐름도 2곳)

## 4. 시뮬레이션 실행 버튼 동작

- 누르면 그때의 브랜드·막힘 조건을 저장하고, 누적 하역량을 0부터 다시 센다. 다시 눌러도 이전 누적값이 섞이지 않는다.
- 실행 후 입력을 바꾸면 "입력 조건이 바뀌었습니다. 다시 실행하세요" 안내가 뜨고, 결과는 마지막 실행 조건 그대로 유지된다. 다시 실행하면 안내가 사라지고 새 결과로 바뀐다.
- 실행 전에는 추천 하역률 자리에 "시뮬레이션 실행 전" 안내를 보여 주고, 컨베이어 수치는 0으로 둔다.

## 5. 추천 하역률의 실제 연결 여부와 한계

| 항목 | 상태 |
| --- | --- |
| 브랜드별 과거 실적 | 연결됨. 최근 2년 총량·일 평균 (기존 집계 값, 원본 재검증 필요) |
| 브랜드별 슈트 막힘 이력 | **연결 안 됨.** 앱에 브랜드별 막힘 횟수·정지시간 데이터가 없음 |
| 슈트 막힘 입력값 | 가상 설정값(3회·45분·1,200 t/h). 실제 이력 아님 |
| 추천 로직 | **검증된 로직 없음.** 브랜드별 "발표용" 운전값을 기존 시뮬레이션 식에 넣은 결과 |

그래서 다음과 같이 표시했다.

- 목록 브랜드: **"가상 조건 기반 참고값"** 배지
- 직접 입력 브랜드: **"이력 부족 · 전체 평균 기준 참고값"** 배지
- 추천 근거에 "막힘 조건은 이번 추천 수치에 반영하지 않음"과 "실제 막힘 이력으로 학습·검증한 추천이 아님"을 명시
- 막힘 조건을 추천 수치에 반영하지 않은 이유: 이력 데이터가 없고, 기존 기준(막힘 손실을 기본 하역량에서 차감하지 않음)을 유지하기 위해서

참고: 같은 Poya 기준 화면의 추천값은 832 t/h이고, 기초자료의 현장 추정(약 1,200 t/h)과는 다르다. 두 값의 기준이 다르므로 비교할 때 주의가 필요하다.

### 추천을 실제로 산출하려면 필요한 것

1. Poya 등 브랜드별 슈트 막힘 횟수·정지시간·청소 이력 (원본 Excel)
2. 브랜드별 화물 수분율 (선박별)
3. 하역 집계 원본과의 대조 검증 (전체 평균 19,114 T/D 등)
4. 막힘·수분율·버켓 속도를 하역률에 연결하는 검증된 로직 (기준 기간과 가동시간 기준 확정 포함)
